# V1/V2配对测试：真实AI验收与体验入口

本阶段只开放QA Preview，不启动Production随机实验，不更改原版GymGoGo资源。两版复用相同PartyGame、Pages Functions、Growth Lab独立quiz-service、QuizBudget与qwen-flash，服务端提示词和1000/300/60/10及金额预留均不改。修复Preview PUBLIC_AI_ENABLED原先为false的问题；生产配置不变。

## 每人统一任务（两版本分别执行）
1. 单人任务：独立找到单人入口，真实开局并完成三次下蹲起立，记录入口、耗时、帮助与计数。单人不含AI，不伪装成有问答。
2. AI任务：创建2人派对（用匿名昵称即可，第二位是占位队友，无需额外真人）；勾选开启AI知识挑战。当前玩家完成第一关2次真实深蹲，等待真实出题，输入一句自己的自然语言答案并只提交一次，观察判定和怪兽吐槽/语音。答对后停在下一位准备状态，不继续做动作；答错则保留失败画面，不重开。退出该派对再切换版本，不恢复上一版答题记录。
3. 每人每版本只做这一道题，不要求整队打完三关；三关玩法仍完整保留，可玩性与本次测试任务范围是两件事。
4. 不将不知道答案当作系统出错，不用提示词干扰模型。正确/错误/无法确定如实记录；模型错误或uncertain立即停下记录，不再生成或提交、不重试，以免超出计划。没有看到真实题目就不填写“AI出题正常”。

## 额度与测试节奏
正常一道题=出题1+判题1=2次，题目和判定采用缓存/操作幂等防重复；创建派对、状态查询、关闭不调用模型。失败/超时可能已经消耗一次，不退还预留、不自动重试。一次AI题不等于完整两人三关派对（后者每人每关题数更多）。
8人×2版×2=32次，10人=40次，另有部署真人验证最多4次。本轮验收前独立账本59/1000，941次剩余，是快照不是承诺实时余额；原5元估算预留上限不是实际账单授权。每分钟最多10次、同网络/来源每日60次，全站每日300次。安排每次AI题前后至少间隔约一分钟，每人测试按原15–20分钟安排；不要刷新/反复提交或组织所有人同时开局触发模型。记录真实消耗，以服务端为准。
两项目共享百炼账号免费Token；独立Worker账本不代表独立免费Token。保持供应商用完即停，不购买或增加限额。

## QA和浏览器状态
分享固定Preview域名，?experience=v1和?experience=v2优先于随机分组；全部事件属于QA，不进入正式实验统计。使用同一设备可按顺序体验，但建议版本间用干净访客环境，避免已看教程/摄像头权限/上一场派对带来偏差。不要清除日常浏览器数据，更不要删除任何D1记录；匿名浏览器ID可变化，研究按手工U编号配对，不能把两个环境当两个真人。

## 真实验证边界
必须由负责人/真实体验者操作摄像头、完成动作与回答。本轮自动测试只Mock，不用API合成结果代替浏览器完整真人流程。真实调用许可最多4次（每版出题、判题各1），不自动重试。入口完成后公布实际URL；Git分支只保存本地，不推master、不部署Production。
